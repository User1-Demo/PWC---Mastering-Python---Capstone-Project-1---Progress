Requests flow in one direction: endpoint → service → model. Endpoints stay thin, and rules like the status workflow live in services/, where they're easy to unit test.

3. What the boilerplate implements
Validation:
Pydantic v2 schemas use regex, ranges, enums and custom validators. Examples are no future incident date, a positive amount, and a password strength check.
A global handler turns validation failures into 422 responses with a field-level errors list (AC-008).
Unauthorized returns a generic 401, forbidden returns 403, and a missing record returns 404. Unhandled errors return a generic 500 and are logged internally.
Auth:
Login and refresh use JWT access and refresh tokens. Refresh tokens are single-use and stored only as hashes.
Five failed logins locks the account for 15 minutes, and the login error message is the same for every failure.
RBAC: require_roles(...) is a dependency you put on every endpoint. Analytics is limited to Manager and Admin (AC-006), and user management to Admin (BR-001).
Claims:
Create checks the policy is active and matches the claim type, then sets the SLA due date.
The list endpoint searches by policy number, claimant or status, with pagination. Adjuster region scoping is done in the SQL query, not in Python.
The status update enforces the workflow. A manager can override with a justification, and high-value approvals are manager-only. Each change writes a history row, an optional note and an audit entry.
Audit: hash-chained log entries for logins, user creation and claim changes.
Placeholders: policies, documents, ai and analytics are stubs with the role protection already wired. ai/query already returns the response shape: answer, citations and no_match.
DevOps: the Compose file runs API, Postgres 16 and Chroma, and there's a CI workflow. Tests cover the workflow rules, a 422 response and the 401 check.
